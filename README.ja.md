# Unified Outliner — 個人用フォーク

[English](README.md)

これは **[kazdonkai/unified-outliner](https://github.com/kazdonkai/unified-outliner)**（Obsidian のノート 1 枚の中で構造編集を行うプラグイン）の個人用フォークです。

プラグイン本体の功績はすべて上流にあります。機能の説明、正規版のインストール方法、スクリーンショット、完全なドキュメントについては、[上流リポジトリ](https://github.com/kazdonkai/unified-outliner)、または[コミュニティプラグインのページ](https://community.obsidian.md/plugins/unified-outliner)を参照してください。このフォークはその代わりになるものではなく、どこにも公開しておらず、1 つの Vault に直接ビルドして配置するだけのものです。

このフォークが存在する理由は、ある特定の使い方のためにいくつかの挙動を変える必要があったからです。すなわち、アウトラインペインからノートの実際のセクションを折りたたむこと、しかも各セクションの中身が下位見出しではなく Dataview ブロックであるようなプロジェクトページで、です。一般的な修正として意味を持つ変更は、その都度上流にも提案しています（状態は下表のとおり）。

## 何が違うのか？

| 変更点 | 上流への提案状況 |
| --- | --- |
| 下位見出しを持たない見出しも折りたためるようにする | 提案済み — [issue #3](https://github.com/kazdonkai/unified-outliner/issues/3) |
| 見出しへジャンプしたときのスクロール余白を設定可能にする | 提案済み — [issue #2](https://github.com/kazdonkai/unified-outliner/issues/2) |
| 見出しレベルごとの一括折りたたみ／展開ボタン | 未提案 |

### 下位見出しを持たない見出しも折りたためるようにする

上流では、子行を持つ行（`children.length > 0`）にだけ折りたたみ用のシェブロンが付きます。ツリーウィジェットとしては正しい判断基準ですが、このプラグインで行を折りたたむとツリーの行が隠れるだけではなく、ドキュメント自身の行範囲を使ってエディタ側の該当セクションも折りたたまれます。つまり、下位見出しを持たず、本文が文章・表・フェンス付きコードブロックだけの見出しは、ドキュメント上には折りたたむべき実体があるのに、ペインからは折りたためませんでした。Obsidian 自身の折りたたみガターなら問題なく折りたためるにもかかわらず、です。

そこで、シェブロンの判定とキーボード操作の両経路が「折りたたむものがあるか？」を問うように変わりました。判定は折りたたみ処理自身が読むのと同じ場所、すなわちノードのドキュメント上の範囲に対する `canCollapseOutlineNode` という述語で行います。これまで折りたためていたものはすべてそのまま折りたためます（新しいケースが増えるだけです）。「折りたたむものがある」とは、見出し自身の行より下に空行でない行が少なくとも 1 行あることを指すので、ファイル末尾で空行だけが続く見出しには、押しても何も起きないシェブロンは付きません。

### 見出しへジャンプしたときのスクロール余白を設定可能にする

上流では、ジャンプ先の行がエディタの最上部にぴったり配置されます。そのため、同じスクロール領域の上部に何かが固定表示されていると（他のプラグインの固定ツールバーや、テーマ自身の固定ヘッダーなど）、ジャンプしたばかりのその行が覆い隠されてしまいます。

**Outline Tree からジャンプする際の上部オフセット（ピクセル）** 設定（0〜1000、既定値 0 = 上流と同じ挙動）を追加し、その値を CodeMirror 既存の `scrollIntoView` の `yMargin` に渡します。スクロール処理そのものを作り直してはいません。

### 見出しレベルごとの一括折りたたみ／展開ボタン

アウトラインツリーの上部に、ボタンの行（`H1`、`H2`、`H3` …）を任意で表示します。表示されるのは、現在のノートで実際に使われている見出しレベルだけです。あるレベルのボタンを押すと、そのレベルの見出しがすべて折りたたまれます（すべて折りたたみ済みの場合はすべて展開されます）。各ボタンのシェブロンは、ツリーの行のシェブロンと同じく、そのレベルの現在の状態を示します。既定ではオフです（**見出しレベルごとの折りたたみボタンを表示**）。

折りたたむ対象がないレベルは、ボタンを隠すのではなく無効状態で表示します。ノートを編集している最中にボタンの並びが動いてしまわないようにするためです。

ボタンはこの変更の小さい方の半分にすぎません。大きい方の半分は、折りたたみ書き込みのバッチ化です。上流の `setNodeCollapsed` は、折りたたみ集合の更新、永続化、開いている他のツリービューの再描画、CodeMirror への折りたたみトランザクションの送出を、ノード 1 つにつき 1 回ずつ行います。これを 20 個の見出しに対して回せば、動作はしても体感は重くなります。現在これは `setNodesCollapsed` への 1 要素の委譲になっており、ノード単位の折りたたみ集合と永続化の書き込みは残しつつ（実際のディスク保存は fold state manager が既にデバウンスしています）、他ビューの再描画は**1 回**、CodeMirror のトランザクションもバッチ全体の折りたたみ効果をまとめた**1 回**だけになりました。このバッチにもツリー由来であることを示す注釈が付いているので、逆方向同期のリスナーはバッチ全体を無視し、1 つ 1 つを往復させることはありません。

上の「下位見出しを持たない見出し」の変更と組み合わさります。プロジェクトページの `## Features` のように Dataview ブロックしか持たないセクションは、あの修正のおかげでそもそも折りたためるようになり、この変更のおかげで兄弟セクションと一緒に折りたためます。

### プラグイン id を分ける

`manifest.json` の id は `unified-outliner-serena`、名前は **Unified Outliner (Serena)** です。これによりコミュニティ版を上書きせず、その隣にインストールされます。あわせて `scripts/deploy-dev.mjs` は、配置先フォルダを上流の id 決め打ちではなく manifest から読むようにしています。フォーク運用上の都合であり、上流に提案することは意図的にありません。

## ビルド方法

上流と同じです。deploy スクリプトに Vault のパスを渡す点だけが追加です。

```bash
npm install
npm test
OBSIDIAN_VAULT="$HOME/path/to/vault" npm run deploy:dev
```

上記の変更にはいずれも、上流のテストスイートと同じ流儀のテストが付いており、スイートは常にグリーンであることを前提としています。

## ブランチ

- `main` — 上流をそのまま追跡（無改変）。
- `serena/local-build` — 実際に配置されるもの。上記の変更をすべてマージしたブランチ。
- `feat/*` — 変更 1 つにつき 1 ブランチ。それぞれ単独で上流に提案できるようにしてあります。
